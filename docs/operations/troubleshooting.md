# Operations — troubleshooting

Living document — add an entry every time something bites you for more than five minutes.

## `pnpm install` fails

- **Symptom**: `ERR_PNPM_IGNORED_BUILDS` followed by exit 1.
- **Cause**: pnpm 11 blocks native build scripts by default and the workspace lists pre-approved ones.
- **Fix**: this is a non-fatal warning — install actually succeeded. The repo's `.npmrc` has `verify-deps-before-run=false` to avoid re-running install on each `pnpm <script>` call. If you still see it, run `pnpm approve-builds` once and pick the listed packages.

## `pnpm db:migrate` errors with "type vector does not exist"

- **Cause**: the migration runs before pgvector is enabled.
- **Fix**: the first generated migration includes `CREATE EXTENSION IF NOT EXISTS vector;`. If you generated migrations on an older Drizzle that omitted it, edit the SQL manually and re-run.

## `/api/health` reports `redis: error`

- Check `docker ps` — is `sahin-redis` up?
- Check `.env` — does `REDIS_URL` point to `redis://localhost:6379`?
- Check Windows firewall isn't blocking 6379.

## Next.js dev server reports `PageProps not found`

- **Cause**: `PageProps` / `LayoutProps` are auto-generated by Next.js during `next dev` / `next build` / `next typegen`. A fresh clone hasn't run any of those yet.
- **Fix**: run `pnpm -F @sahin/web dev` once (or `pnpm -F @sahin/web exec next typegen`) before typechecking. Alternatively, type your route props explicitly — that's what the Phase 1.0 skeleton does.

## Worker exits immediately with "Postgres ping failed"

- The worker boot pings DB + Redis before registering queues. The failure is intentional — running with a bad connection would silently lose jobs.
- Run `pnpm db:up` and wait for the Postgres healthcheck (a few seconds) before starting the worker.

## Worker schedules don't fire

- **Cause**: `WORKER_SCHEDULES_ENABLED=false` in `.env` (the Phase 1.0 default — scrapers don't exist yet).
- **Fix**: flip to `true` after Phase 1.1 lands and the Armut scraper is real.

## Scraper hits a login wall

- See [`playwright-auth.md`](playwright-auth.md) — re-run `pnpm setup:<platform>`.

## Theme toggle flickers on first load

- Expected — `next-themes` reads from `localStorage` after hydration. `suppressHydrationWarning` on `<html>` and `disableTransitionOnChange` mitigate it. If it's actually disturbing, add a `themeColor` script in `<head>`.
